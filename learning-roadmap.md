# Learning Roadmap

## Principle

Courses are useful only if they create evidence. Every learning unit should improve this repository through a document, template, case study, dashboard, or technical understanding note.

## Path

| Order | Course / Track | Portfolio Output |
|---:|---|---|
| 1 | IBM IT Project Manager | SDLC summary, risk log, project charter, capstone notes |
| 2 | Software Product Management | Product requirements, user stories, backlog, release plan |
| 3 | IBM Product Owner selective modules | Backlog refinement, stakeholder plan, Product Owner capstone artifact |
| 4 | Git / GitHub / terminal / Python / Docker basics | Repo hygiene, technical setup notes, small automation demos |
| 5 | DataTalksClub LLM Zoomcamp | RAG / evals / monitoring case study connected to Feintt.ai |

## Weekly Operating Rhythm

- 3 learning sessions per week.
- 1 portfolio artifact update per week.
- 1 weekly review: what was learned, what was built, what is still unclear.

## Completion Criteria

The path is successful when a hiring manager can see:

- Technical delivery vocabulary used correctly.
- Clear artifacts, not only certificates.
- Realistic understanding of software delivery.
- Evidence of AI/LLM workflow thinking.
- Honest separation between real experience, simulation, and learning.
